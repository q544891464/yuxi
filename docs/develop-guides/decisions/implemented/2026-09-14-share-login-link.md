# 用户分享登录链接

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/share_login_service.py

## 问题

平台需要为指定普通用户生成可分享的登录链接。持有该链接的访问者应以该用户的权限进入 `/chat`，且管理员能够随时撤销链接。

## 决策

新增独立的分享登录链接事实。服务端只保存随机密钥的 SHA-256 哈希、目标用户、创建人、撤销时间和最近使用时间；原始密钥只在创建响应中出现一次。管理员只能管理自己部门的用户，超级管理员可管理全部用户，且不能为超级管理员创建链接。

前端使用 `/login#key=...` 承载密钥。片段不会随 HTTP 请求或 Referer 发出；登录页完成一次无认证交换后立即清除片段，并写入平台既有 7 天访问会话。分享链接本身不设到期时间，但撤销后不能再换取新会话。

## 替代方案

把既有 API Key 或 JWT 放入查询参数会授予长期 API 凭据、进入访问日志，并且无法单独撤销分享登录用途，因此不采用。使用 URL 查询参数会使密钥进入服务器日志和 Referer，因此不采用。

## 风险

链接持有者可获得目标用户当前全部权限，因此应只分发给可信访问者。撤销仅阻止后续链接交换；已建立的既有 JWT 会话按现有 7 天会话策略结束。

## 后果

管理员在“设置 → 用户管理”中仅能为普通用户生成和撤销链接。原始密钥只在创建弹窗出现一次；管理列表只保留创建、撤销与最近使用记录。浏览器使用 URL 片段承载密钥，并在交换前清除片段。

## 验证

`web/test/unit/entry_redirect.test.js` 覆盖已有会话访问 `/login#key=...` 时仍进入登录页；前端 lint、全部 337 项单元测试和生产构建通过。后端针对性 ruff 与编译检查通过；认证 API integration 测试已覆盖生成、交换、撤销、未知密钥、超级管理员目标和跨部门拒绝。由于本机没有 Docker 且 Windows 不具备 Linux 文件系统常量，PostgreSQL integration 在部署环境执行。
