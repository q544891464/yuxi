# 终态竞争单测隔离用量读取

状态：implemented
类型：testing
Owner：backend/test/unit/services/test_run_worker.py

## 问题

终态竞争单测隔离了终态写入，却未隔离后来新增的 token 用量读取。真实调用堆栈显示该测试初始化 PostgreSQL manager 和 psycopg 连接池，单测退出时可能停留在异步后台任务清理。

## 决策

在该测试中为用量读取提供无用量的确定性结果，保留终态竞争失败者不发布 end 事件的断言，并断言数据库 manager 没有被初始化。不改变生产连接池或 Worker 清理逻辑。

## 替代方案

在测试结束后关闭真实连接池仍让 unit 依赖数据库；修改生产生命周期缺少线上缺陷证据。

## 验证

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
|---|---|---|---|---|---|
| 竞争失败者不发布 end，单测不初始化真实池 | 单测遗漏依赖 | test_run_worker.py | Worker 单测、标准全量命令 | 移除用量隔离会触发初始化断言 | Passed |

## 后果

该结果只说明单测隔离问题；生产取消、lease 及连接池生命周期保持不变，不声称此变更修复线上执行。

Worker 51 项单元测试通过。补齐会话查询夹具后，未加载诊断插件的完整后端 unit（not slow）2152 项通过，异步 teardown 正常完成。

负向验证在隔离副本移除用量读取 mock，测试明确因数据库初始化被调用 1 次失败。
