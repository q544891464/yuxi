# 将对话移动到项目

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/conversation_service.py

## 问题

侧栏中的对话只能按创建时的项目归属展示，用户无法把已有对话整理到其他项目。

## 决策

线程更新接口接受可选的 `project_id`。服务层先锁定当前用户的 active/selectable 目标项目，再锁定对话，保持与删除项目一致的锁顺序；目标项目权限和状态由后端校验。目标目录不可用、对话存在运行中 Run 或排队请求时拒绝移动；已有子智能体线程的父对话也拒绝移动，以保持父子线程的项目一致性。前端在会话操作菜单中提供“移至项目”子菜单，成功更新线程后复用现有响应更新侧栏分组。

移动只改变对话的项目归属，不搬迁项目工作目录中的既有文件。后续请求使用目标项目工作目录，附件和旧目录文件不会自动复制或删除。已建立父子子智能体线程关系的父对话和子对话均不可移动，以保持两端项目归属一致。

## 替代方案

- 只在前端修改项目分组：无法形成权限边界，也会在刷新后丢失。
- 移动整个项目工作目录：会引入文件冲突、覆盖和回滚语义，本次只改变对话归属。

## 后果

- 用户可从项目对话或最近对话的操作菜单选择另一个可用项目。
- 当前项目会从候选列表中排除；没有其他可用项目时显示空状态。
- 正在运行或排队的对话需要等待完成后再移动。
- 已建立子智能体线程关系的父对话或子对话暂不能移动，避免后续子线程续跑时出现 Workdir 不一致。
