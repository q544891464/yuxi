# 从业务定制版收敛通用 Basic 版

状态：implemented
类型：simplification
Owner：web/src/router/index.js

## 问题

`cydx` 的登录、聊天欢迎页、数字人形象、角色、左侧业务技能树和文书移交围绕税务稽查/审理/督查设计。直接把同一界面作为通用平台交付，会展示无关的身份、材料提示、知识库 ID 和业务流程；只改文案仍会暴露这些专属入口。

## 决策

`basic` 以当前 `cydx` 为基线，保留通用对话、项目、附件、知识库、Skills、智能体和管理能力。`/chat` 成为唯一普通聊天入口，旧 `/chat/ducha` 地址跳转到 `/chat`。登录、欢迎页和标题使用通用 Yuxi 文案。移除督查数字人选择、税务素材和左侧预设技能树，项目新会话直接进入空白对话；个人与共享 Skills 仍通过扩展页和输入框引用使用。停用税务专属的内置报告解析 Skill、事实证据审查子智能体和正式文书流转入口/API。普通账号与管理员权限保留，税务业务角色不再可新建或配置。

持久化的旧文书表和旧配置记录不自动删除；Basic 部署必须使用独立数据环境，既有 `cydx` 业务数据保持原状。通用 Skills、知识库和文件解析器不因业务入口删除而移除。

## 替代方案

- 保持旧 `basic` 不合并：会失去 70 个提交里的通用上传、对话、归档及运行稳定性修复。
- 仅隐藏菜单并替换文案：后端接口、默认内置 Skill 与可直达路由仍保留税务流程。
- 迁移时直接删数据库表/用户 Skill：会破坏现有数据；数据处置应由独立迁移任务决定。

## 后果

旧 `cydx` 数据库中保存的品牌、角色和个人/共享业务 Skill 不由代码删除；若错误地复用该数据库，仍可能显示旧配置或保留历史资源。Basic 需要独立部署配置与数据。移除接口时要核对前端、公开契约、测试和 migration consumer；停用业务表不意味着可以原地降级数据库 Schema。

## 验证

`web` 的完整单元测试 366 项通过，lint 与 build 通过；Vite 页面验证未登录访问 `/chat` 跳转至 `/login?redirect=/chat`，登录页显示通用文案。`docs` 构建和工程契约检查通过。后端修改文件通过 Ruff 与编译检查。Windows 缺少项目要求的 POSIX 文件描述符能力，后端 pytest 在收集阶段失败；本机无 Docker，真实 HTTP、工作区聊天和后端全量测试未验证。工程契约单测在 Windows 遇到 `/etc/hosts` 链接权限和路径分隔符断言问题，未全通过。

旧能力不存在：发布入口与默认注册中不含税务定制的业务技能导航、督查页面、税务报告解析、事实证据审查和正式文书流转；源码与测试可保留历史说明，但不能有可调用的当前入口。

重新引入条件：某个部署明确要求行业插件时，以独立模块和独立权限/数据契约接入，不回填 Basic 的默认导航与核心启动流程。
