# 保留系统配置的合法写入入口

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/config/options.py

## 问题

通用配置的内部标记用于隐藏表单。对所有带此标记的记录统一禁止写入，会连同管理员系统设置的专用保存入口一起阻断。系统设置已有代码定义字段校验，文书流程则由独立服务拥有权限和版本语义。

## 决策

允许已有 system_options 定义通过字段校验后写入，保留其他内部配置的拒绝行为。管理员权限仍由路由依赖执行。

## 替代方案

取消全部内部写入保护会让通用入口返回文书配置。增加可绕过任意内部记录的参数扩大权限表面，没有当前需要。

## 验证

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
|---|---|---|---|---|---|
| 管理员可保存系统设置 | 内部标记误拦截 | config/options.py | 真实 HTTP 单项及批量保存后重新查询 PG | 原 guard 使保存返回400 | Passed |
| 文书内部配置不能走通用入口 | 越权读取/更新 | config/options.py | 既有文书 HTTP 集成 | 空值更新也拒绝 | Passed |

## 后果

只放行代码拥有字段定义的 system_options，未改变管理员授权、其他内部配置或敏感字段返回规则。

真实 HTTP、独立 PostgreSQL、私有 MinIO 及相关迁移/OCR 回归共 41 项通过。完整后端回归在任务执行测试的异步 teardown 阶段停留；加入临时异步任务诊断后运行至 1669 项通过，随后在共享技能管理的既有权限预期上失败。诊断改变调度时序，未声明标准全量命令通过。
