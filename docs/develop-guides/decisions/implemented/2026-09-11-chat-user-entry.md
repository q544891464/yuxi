# 普通用户聊天入口

状态：implemented
类型：feature
Owner：web/src/router/index.js

## 问题

普通用户需要独立聊天入口及面向业务的欢迎界面，不进入管理员工作台。

## 决策

`/chat` 和 `/chat/:thread_id` 复用 AgentView 与 AgentChatComponent。AppLayout 隐藏配置导航，顶部保留品牌和用户信息，左侧常驻可折叠的历史对话与新建入口；欢迎区域独立滚动，输入框位于聊天区域底部。普通用户默认进入 `/chat`，管理员默认进入 `/agent`；普通用户直接访问或登录回跳 `/agent` 会转到 `/chat`。后端现有用户、对话与文件授权仍然执行，完成聊天所需的 API 保留。

ChatWelcome 拥有业务欢迎文案、建议问题和蓝白展示；建议问题只填入草稿，不自动发送。素材通过 CSS 图像窗口仅展示独立盾形标志和人物，横版品牌文字不展示，平台名使用真实文本。统计数字暂不展示，后续只能使用真实数据。

## 替代方案

复制聊天实现会让流式输出、附件、审批和重试行为分叉，因此仅扩展现有组件展示插槽与路由目标。隐藏全部会话导航会破坏历史恢复，使用常驻左侧历史导航，减少会话切换步骤。

## 后果

线程创建、切换、删除和恢复使用当前入口的路由名称。前端限制页面体验，后端资源权限仍为最终边界。本变更不扩大普通用户资源可见性，也不禁用现有聊天工具与附件能力。

## 验证

- `node --test test/unit/entry_redirect.test.js`：7 项通过，覆盖管理员、普通用户、过期会话、直接工作台访问及登录回跳。移除工作台 requiresAdmin 即会恢复普通用户进入工作台的目标缺陷。
- `pnpm run lint:check`、`pnpm run test:unit`、`pnpm run build`：通过，前端共 324 项测试。
- 真实浏览器：普通测试用户登录进入 `/chat`、直接访问 `/agent` 回到 `/chat`；管理员测试用户登录进入 `/agent`。
- 普通测试用户完成附件上传和模型回复，新建与历史恢复均保持 `/chat` 路由；刷新后消息和附件记录仍可见。桌面、手机及深色消息界面已检查。PC 侧栏与底部输入框布局在欢迎页和实际发送后的对话页再次验证，手机专项适配暂不纳入本次布局调整。
- 后端 API 与执行链路没有修改；测试未逐项重复所有工具审批、重试及导出流程，这些功能继续使用同一聊天组件。
