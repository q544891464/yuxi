# 技能分层导航与引导式对话入口

状态：implemented

类型：feature

Owner：web/src/layouts/AppLayout.vue

本文供维护业务入口的前后端开发者使用，需要了解现有 Skill 引用、项目和 AgentRun 请求链路。记录覆盖导航、说明、草稿和权限决定；实现已在工作树中完成，真实服务联调和部署不属于已验证结果。

## 问题

用户需要按业务事项找到技能，了解准备材料和预期结果，再上传材料并手动发送。入口需要同时支持全局导航和指定项目的新会话，并保持现有欢迎人物、资源统计以及底部输入框。

## 决策

### 导航与说明

左侧业务页面提供“技能”折叠菜单和现有技能管理入口。菜单层级如下；有子项的业务名称可以调用整包技能，独立箭头负责展开收起。项目加号在项目内展开同一菜单，并提供“不使用技能，直接对话”。收起侧栏保留打开技能菜单的按钮。

```text
技能
├─ 添加技能
├─ 撰写稽查报告
│  ├─ 申报数据处理
│  ├─ 发现问题导入
│  ├─ 生成稽查报告
│  └─ 校验稽查报告
└─ 撰写审理文书
   ├─ 校验稽查报告
   ├─ 生成审理文书
   ├─ 判断案件性质
   │  ├─ 重大案审
   │  ├─ 一案双查
   │  ├─ 黑名单
   │  └─ 移送公安
   └─ 审理台账
知识库
数据总览（管理员）
```

欢迎页保留主形象和资源统计；原预设问题区域显示技能说明卡。卡片说明所需材料、用途和结果，提供明显的“上传材料”按钮。输入框保留底部位置，说明内容可在上方区域滚动。选择技能只准备草稿，用户点击发送后才进入正常对话。

### 映射与材料

菜单、材料说明和预设提示词由 PostgreSQL 导航配置拥有，默认值随 `backend/package/yuxi/config/static/skill_navigation.json` 发行；管理员维护方式见[侧栏技能配置决定](./2026-09-17-configurable-skill-navigation.md)。`web/src/utils/skillEntries.js` 只负责查找与引用转换。撰写稽查报告及子项复用 Audit Report Writer，申报数据处理单独使用 Vat Surtax Recalc；撰写审理文书及其子项复用 Ai Assisted Review。功能拆分由未来实际 Skill 的安装和映射修改完成，本入口不创建新的技能或自动工作流。

| 功能 | 输入材料 | 预期输出 |
|---|---|---|
| 申报数据处理 | 申报表、净入库数据 | 数据表格、稽查报告第二页汇总表 |
| 发现问题导入 | 检查人员问题、工作底稿、银行流水、开票信息、企业基本情况 | 问题验证报告、计算过程校验 |
| 生成稽查报告 | 前两项输出、正式报告模板 | 稽查报告草稿 |
| 校验稽查报告 | 报告、申报表、入库表、底稿、流水、发票 | 准确性校验及差异依据 |
| 生成审理文书 | 正式稽查报告 | 审理报告、处罚决定书等文书草稿 |
| 判断案件性质 | 案件事实、证据和相关文书 | 四类事项的适用分析、依据及待人工确认内容 |
| 审理台账 | 审理报告、税务处理决定书、处罚或不处罚决定书 | 审理台账及缺失项 |

绑定在当前 Agent 允许且用户可访问的 Skill 列表中匹配配置的实际 slug，实际引用使用返回的 slug。缺失、禁用或匹配不唯一时显示不可用并禁用入口上传和发送，不伪造技能引用。切换 Agent 不自动扩大技能权限。

### 草稿、附件和发送

`AgentChatComponent.vue` 拥有选中技能、真实 mention token 和预设文本；`AgentView.vue` 将路由中的技能与项目意图交给组件。人工修改草稿后再换技能，需要选择保留草稿或替换提示词。临时草稿按用户、Agent 和项目区分，已有线程沿用现有线程草稿机制。

上传复用现有附件窗口与线程创建逻辑；发送复用现有 AgentRun 请求链路。导航不会自动执行模型，也不改变 FIFO、SSE、取消、审批、上传大小或沙盒路径规则。浏览器请求中的技能 token 是后端现有技能权限检查的输入，前端映射不构成授权。

### 知识库与数据总览

知识库入口指向业务指定的知识库详情。登录用户必须通过资源读取权限校验；普通用户只能读取和检索，详情响应强制使用 read 级别的序列化，隐藏管理能力、连接敏感配置和共享用户/部门明细。写入继续要求管理员及资源 manage 权限。评估后台保留管理员边界，私人知识库不会因增加入口而变为全局可读。

Dashboard 路由及两个统计后端入口允许 admin 和 superadmin，普通用户被后端拒绝。这意味着管理员可以查看现有全平台统计，沿用既有 Dashboard 的数据范围。读取和写入权限分别由 `server/utils/knowledge_permissions.py`、现有资源权限逻辑以及路由依赖拥有。

## 替代方案

只显示技能列表不能说明业务材料；复制一套上传与发送逻辑会产生独立的线程和权限边界；为每个菜单项创建空技能会把未实现能力伪装成可执行能力。当前选择复用三个真实技能，由各入口预设文本表达不同业务任务。

欢迎区域完全替换为技能页会移除用户要求保留的主形象；在欢迎页原问题区域加入说明卡能保持页面结构。分组名只用于展开会使现有整包技能缺少直接入口，因此分组名称与展开箭头使用独立操作。

## 后果

子功能的执行质量取决于当前整包 Skill 内容和用户提供的材料；本次界面不保证业务输出已满足最终文书要求。普通用户知识库读取仍取决于管理员既有共享设置。真实安装名称、可见性和目标知识库的数据需要在目标环境联调，浏览器模拟接口不能证明它们存在。

## 验证

目录映射与错误绑定由 `web/test/unit/skillEntries.test.js` 验证；项目草稿隔离由 `web/test/unit/thread_draft.test.js` 验证。浏览器在 1280×720 和 1920×1080 检查说明区、底部输入框、项目技能选择、上传弹窗、草稿保留/替换、无技能入口，以及发送请求携带的项目与技能。浏览器使用明确的模拟 API，未调用真实模型。

后端权限负向案例在知识库读取和 Dashboard 的 unit/API integration 测试中维护，包括非共享资源拒绝、普通用户不能写入、写入拒绝后的数据未改变和普通用户不能访问统计。Windows 本地缺少 POSIX 沙盒运行支持，Docker 环境不可用，后端测试及真实服务 E2E 未执行通过。完整命令与结果随交付记录提供；未部署。
