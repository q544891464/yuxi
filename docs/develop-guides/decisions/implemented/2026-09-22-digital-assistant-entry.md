# 数字人选择入口与督查形象

状态：implemented
类型：feature
Owner：web/src/router/index.js

## 问题
登录后有多个业务入口的用户需要选择稽查或督查数字人，督查品牌需要独立男性形象。

## 决策
复用服务端角色页面决策返回的允许页面，不增加角色或资源权限。普通登录与根入口进入数字人分流：两个业务入口可用时显示选择页，一个可用时直达，没有可用业务入口时保留配置首页。显式会话深链接与 CLI 授权继续进入原目标。选择页直接访问也进行认证与权限重读，点击进入工作区时再次经过原守卫。督查欢迎页和输入框使用独立透明男性素材，稽查形象保留。

`digitalAssistants.js` 拥有两个业务入口的展示资料；`AssistantSelectionView.vue` 投影已允许的卡片。角色及资源授权继续由原服务端执行，前端选择不授予权限。

## 替代方案
增加独立数字人权限会与已有页面配置重复；要求所有用户选择会增加单入口用户操作。保留已有页面范围作为唯一来源。已有会话链接保留原目标，避免选择造成定位丢失。

## 后果
现有用户角色仍为单角色；多个权限指该角色允许的多个业务页面。默认业务登录优先数字人选择或唯一入口，只有无业务入口的用户保留后台配置首页。督查素材由用户图片经 imagegen 提取，保留透明通道并存入项目；输入框装饰继续使用原定位容器和固定尺寸，不参与布局。

## 验证
前端路由与数字人名单相关 19 项测试通过，覆盖密码/OIDC 首页、多入口选择、单入口/零入口分流、深链接、伪造 hash 和权限失败恢复；全量前端 403 项通过。真实 Vue 浏览器配合隔离 API fixture 验证两个卡片分别进入正确页面，督查登录与手输选择页均直达督查，1280×720、1920×1080、390px 宽无横向溢出，浅色/深色均可见人物。正式对话的督查 mascot 为原 composer-shell 定位，157px 高且 pointer-events:none。素材为 RGBA，alpha 范围 0～255，尺寸 1145×1374，轮廓无巨大透明占位。

本次不改变后端 API，未部署。后端全量检查仍受到隔离 Linux 中未修改 scripts/init.sh 的 CRLF 换行问题影响，不能声称全量后端通过。
