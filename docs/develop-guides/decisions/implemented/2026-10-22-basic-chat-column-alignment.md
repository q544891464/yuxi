# 消费端消息正文与输入框共用中心线

状态：implemented
类型：bug-fix
Owner：web/src/layouts/AppLayout.vue

## 问题

消息区限制为 760px 并靠输入框右侧对齐，输入框限制为 1060px 且居中。真实页面在 1920×1080 下消息中心偏右 150px，在 1280×720 下偏右 120px。仅验证人物不遮挡文字无法发现这种阅读区域偏移。

## 决策

### 实现方案

`AppLayout` 统一消费端消息区和输入框的水平中心线。消息区移除内部横向 padding，正文最大宽度为 700px，接近原来 696px 的有效阅读宽度；聊天主区域两侧对称保留人物所需空间。主区域宽度不超过 960px 时隐藏装饰小人并释放水平留白，确保缩窄窗口或展开右侧面板后正文仍有足够宽度。

人物继续由 `AgentView` 提供，绝对定位于实际输入框的 `composer-shell`。输入框高度、首页布局、消息滚动和运行状态语义保持原有 Owner，未增加人物垂直占位。该规则细化[通用数字员工聊天布局](2026-10-22-basic-employee-chat-experience.md)的横向避让约束。

## 替代方案

仅将原消息区居中会在中等宽度下与人物相交。通过垂直 padding 为人物留空会再次扩大消息与输入框的距离。根据 viewport 单独调整 left 值无法覆盖侧栏折叠和右侧面板占用空间，容器查询以真实可用宽度决定装饰是否显示。

## 后果

常见桌面宽度下人物保留在输入框左上沿；紧凑布局优先保留正文阅读空间。宽屏正文仍保持有限行长，消息区和输入框不需要同宽即可对齐。

## 验证

浏览器使用实际 Vue 页面与隔离 API 数据，比较消息列和输入框中心、人物与正文的矩形交集、输入框包装高度以及滚动末端可见性。1920×1080、1440×900、1280×720 下中心误差均为 0px，短消息和长正文均不与人物相交；侧栏折叠、右侧文件面板、375px 与 900px 窄屏、深色和首页检查通过。恢复旧对齐规则后，相同验收函数因中心偏差 150px 拒绝。可复用入口为 [chatColumnAlignment.js](../../../../web/test/browser/chatColumnAlignment.js)。

前端 lint、生产构建与文档构建通过。前端全量单元测试 470 项中 468 项通过；知识库只读入口的源码正则和项目空态文案断言两项失败，在未修改的基线源码中独立复现，相关文件不属于本次改动。隔离 Linux 环境中后端非 slow 单元测试 2621 项、工程契约与离线脚本单元测试 84 项均通过；Windows 工程契约单测的符号链接创建受本机权限限制，Linux 补验通过。页面 fixture 仅证明真实组件的布局行为，不声明模型调用或完整离线栈已通过。
