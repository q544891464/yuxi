# 大型 ZIP 附件与受限解压

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/attachment_service.py

## 问题

案件材料需要批量上传。聊天附件的 5 MB 限制不满足需求，直接放开容量会导致整包内存读取与无界解压。

## 决策

普通聊天附件最多 10 MB，ZIP 最多 200 MB，字节单位按 1024 换算，包含等于上限的文件。ZIP 按文件后缀选择额度，同时验证真实 ZIP 格式；目录与文件合计最多 1,000 个条目，实际解压总量最多 1 GB。拒绝加密条目、重复路径、绝对路径、父级路径、链接与特殊文件。上传和确认附件均重新校验，超限返回 400；流式读写以临时磁盘文件中转 MinIO 与当前 Workdir。网关允许 210 MB 请求体，为 multipart 留出余量。

Agent 的 `extract_zip` 工具默认可用，从受信任 runtime 确定用户和当前项目，使用 no-follow Workdir 文件边界。工具再次校验归档，在临时目录完成解压后写入项目中的独立目录；失败清理本次目录。解压不递归处理内层压缩包，不自动执行其中程序。用户看到解压后的目录、文件数和字节数。

在 ZIP 库加载目录前，有界扫描 EOCD／ZIP64 与真实目录记录，防止伪造条目数导致预检查前内存膨胀。目录元数据最多 8 MB；仅支持单卷归档。

## 替代方案

无上传上限无法控制内存和磁盘消耗。仅提高 Nginx 限制不能解除服务校验。仅用 prompt 要求 Agent 小心解压无法在工具执行入口实施限制，因此提供有界解压工具。

## 后果

较大附件消耗临时磁盘，校验 ZIP 需要完整读取解压内容；每次归档限制不是用户存储配额。Agent 的通用代码执行能力仍可操作其沙盒内文件，本工具不能替代沙盒磁盘配额。头像等其他上传入口保持各自限制。

## 验证

- 隔离 Linux 容器中的附件、ZIP、模型附件上下文与工具注册相关测试：60 passed，覆盖普通附件 6 MB、10 MB、10 MB 加一字节，以及 ZIP 文件数、压缩大小、解压大小、路径穿越、链接、伪造格式、真实 Workdir 读写和失败回滚。伪造目录计数与超大元数据测试确认拒绝发生在 ZipFile 构造之前；单卷 ZIP64 成功案例通过。
- 真实 TCP HTTP 路由与一次性 MinIO 集成：1 passed。6 MB／10 MB 普通文件和 11 MB／200 MB ZIP 上传成功，10 MB 加一字节的普通文件、200 MB 加一字节的 ZIP 及伪造 ZIP 返回 400；上传 ZIP 回读 SHA256 与源文件一致。认证替换为固定测试身份，不声明生产认证或真实模型链路验证。
