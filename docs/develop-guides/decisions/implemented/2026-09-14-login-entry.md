# 登录入口与聊天页视觉统一

状态：implemented
类型：bug-fix
Owner：web/src/router/index.js

## 问题

用户反馈未登录直达 `/chat` 空白，登录页与聊天页风格不同。线上全新浏览器访问已能跳转，但启动组件在身份校验完成前依据残留 token 初始化智能体，会产生重复认证请求。原守卫还依赖 sessionStorage 写入，存储受限会中断导航。

## 决策

路由守卫通过登录页 query 传递回跳路径；LoginView 校验路径后回跳。App 在首个路由解析期间显示加载提示，智能体初始化由已认证的工作区组件负责。登录页与聊天页共享背景和品牌颜色，使用既有盾牌素材、单列表单与圆角卡片。管理员默认进入 `/agent`，普通用户默认进入 `/chat`；后端授权不变。

## 替代方案

保留会话存储并吞掉写入异常会丢失深链接；在 App 重复初始化会与守卫身份恢复竞争。直接移除路由校验不可接受。

## 后果

回跳路径可见于 URL，仍仅允许站内路径。存储受限修复范围为匿名入口和密码登录回跳，OIDC 的跨站会话存储契约保持不变。此项是局部入口修复，直接记录已实施决定，没有迁移或需要先裁决的外部接口变更。未能复现用户浏览器原始空白状态，不将潜在失败路径认定为其唯一原因。

## 验证

`web/test/unit/entry_redirect.test.js` 使用实际路由表，覆盖匿名直达、深链接、过期会话和普通用户工作台限制；存储抛错用例恢复旧守卫会中断导航。真实浏览器验证登录页渲染、回跳与加载状态，完整前端 lint、unit 和 build 作为提交 gate。
