# 消费端知识库与数据总览保持工作区外壳

状态：implemented
类型：feature
Owner：web/src/router/index.js

## 问题

`/chat` 左侧的知识库和数据总览入口分别跳到 `/extensions` 与 `/dashboard`，路由切换后消费端顶部栏、技能和项目侧栏随之消失。用户只是查看业务资料，却被带到另一套后台导航，当前对话也失去视觉上下文。

## 决策

在 `/chat` 下增加静态子路由，复用现有知识库详情和数据总览组件。消费端按钮进入这些子路由，使 AppLayout 的品牌、项目、技能和会话侧栏保持不变，右侧主区域替换为对应内容。两个子路由参与既有 `keep-alive`，入口同时携带当前 `/chat` 地址；返回地址只接受 `/chat` 首页或单段会话路径，恢复线程、草稿与技能引用且不形成开放重定向。后台原路由和权限不变，数据总览子路由继续声明管理员权限。

普通用户查看只读知识库时，文件上传弹窗不再请求管理员专属的文件类型配置接口；组件使用本地默认类型且不显示无关错误。管理员仍从服务端读取配置。

## 替代方案

- 用 iframe 嵌入后台页面：拒绝，会产生重复导航、认证和高度滚动问题。
- 在 AppLayout 内用本地布尔状态直接切组件：拒绝，浏览器返回、刷新和可分享 URL 语义丢失。
- 仅修改跳转动画：拒绝，不能保持当前工作区外壳。

## 后果

- 知识库与数据总览同时拥有后台入口和消费端工作区入口，URL 能直接表达当前右侧内容。
- 资源页参与消费端 `keep-alive`，因此再次进入时保留组件状态；需要主动刷新数据的页面仍由自身刷新动作负责。
- 知识库详情的高度和滚动由右侧主区域约束，避免独立 viewport 页面嵌入后出现双滚动。
- 文件类型默认值继续服务只读用户；服务端配置只影响具备上传权限的管理员。

## 验证

- `node --test test/unit/consumerWorkspaceRoutes.test.js test/unit/file_upload_folder.test.js`：7 项通过，覆盖静态子路由顺序、管理员权限、返回路径和普通用户不调用管理员接口。
- `pnpm run lint:check`：通过。
- 真实 Chrome 1920×1080 与 1280×720：知识库显示在品牌顶栏和业务侧栏右侧，无横向溢出，控制台零错误。
- 从 `/chat` 往返 `/chat/knowledge/kb_a2rvesuax2` 后，`skill-creator` 引用及完整未发送提示词保持不变。
- 知识库面包屑和资源页品牌链接都使用受限的 `returnTo`，覆盖 `/chat/:thread_id` 与 `/chat?skill=...`，非法外部或嵌套资源地址回退 `/chat`。
