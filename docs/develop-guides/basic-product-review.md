# Basic 数字员工平台产品审查

## 阅读范围与证据

本文面向产品负责人、设计人员和开发者，记录 Basic 通用数字员工平台的产品问题、竞品参照与优化方向，供选择迭代范围使用。读者需要了解员工、会话、项目和知识库的基本概念。首轮交付范围与验收由[首轮整改执行提案](./decisions/proposed/2026-10-22-basic-product-first-round.md)维护；本文保留审查背景，不维护独立的工程主张编号或完成清单。

审查日期为 2026-10-22，初始源码基线为 `basic@715ce2c5`，落档核对基线为 `9dd2ceab`。证据包括分支源码，以及员工广场、聊天、员工创建、技能、定时任务和数据总览的管理员页面只读走查。页面构建版本与 Git 提交未逐一匹配，部署页面观察与分支源码结论分别说明。竞品依据同日查阅的官方资料，只比较能力与组织方式，不构成同模型、同任务的效果排名。

源码与页面检查记为 `Inspected`；新用户理解成本和产品收益判断记为 `Inferred`。真实模型回答质量、知识检索、任务耗时、跨账号完整使用链路和普通用户可用性测试均为 `Not run`，原因是本次只读审查没有创建测试资源或提交模型任务。后续产品验收需要在隔离环境补齐这些证据。

`9dd2ceab` 已实现知识库与技能管理拆分、删除重复管理工作台入口、侧栏技能配置迁入技能管理。相关问题按[管理导航拆分决策](./decisions/implemented/2026-10-22-management-navigation.md)核对，首轮只做回归与剩余术语收敛，不重复开发。满意度无样本和后台任务结果已完成首轮修复，事实与证据见[实现决策](./decisions/implemented/2026-10-22-dashboard-task-results.md)；下文保留审查基线的问题与建议，其余建议不代表功能已交付。

## 产品定位与已有能力

评审假设目标客户是私有部署环境中的企业知识工作者、业务搭建者和平台管理员。核心价值是让用户容易交办工作、确认成果，让业务负责人持续改进员工质量。当前界面以聊天和技术配置为中心，建议围绕岗位任务组织入口、能力说明和运营指标。这是产品取舍，仍需用真实部门试点校准。

Basic 已有员工广场与账号默认员工、项目和个人空间、附件与成果预览下载、知识库及引用、技能（Skills）、工具连接协议（MCP）、子智能体、定时任务、工具审批、部门共享、OIDC 登录、用户反馈和统计。知识库评估提供页面入口，智能体评估通过 CLI 与 Langfuse 执行。优化应复用这些能力，区分入口不清、使用门槛高、产品流程未连通与真正缺失的功能。

现有事实分别由[员工配置](../agents/agents-config.md)、[知识库教程](../intro/knowledge-base.md)、[智能体评估](../agents/agent-evaluation.md)、[第三方认证](../advanced/third-party-auth.md)及仓库根 `ARCHITECTURE.md` 的架构地图说明。本文不评定模型效果或基础设施可靠性，也不把已有权限、定时任务、审批和反馈列为重新建设项目。

### StaffDeck 对照后的迭代取舍

StaffDeck 的[核心流程与能力说明](https://github.com/OpenBMB/StaffDeck/blob/main/README.zh.md)把员工资料、能力配置、工作过程和运营反馈串联起来。以下是针对 Basic 的产品取舍；没有部署 StaffDeck，也没有对其实现完整性、执行效果或可靠性进行实测。

| 对照维度 | StaffDeck 官方描述 | Basic 的优先动作 |
|---|---|---|
| 员工定位 | 岗位、能力档案及预置岗位员工 | 首轮让预置员工清楚说明能做什么、需要什么、交付什么；岗位模板库由部门试点之后再扩展 |
| 搭建流程 | 创建员工后配置知识、技能、SOP 与工具 | 首轮把已有配置、依赖提示与试运行入口连通；保留创建者显式选择访问范围 |
| 工作连续性 | 执行观测、排队、取消和必要时介入 | Basic 已有执行与审批基础；首轮补齐个人工作找回和待处理事项入口，不重复建设调度引擎 |
| 标准流程 | 结构化 SOP、可视化编辑及版本管理 | 后续从一个可复用业务流程验证需求，再决定流程画布与版本边界；首轮保留明确输入和交付要求 |
| 知识使用 | 结构感知检索、引用与调试 | Basic 已有知识库和引用；先改善可用性说明、依赖检查和处理结果，再用同一文档与问题集评价检索差异 |
| 服务触达 | 微信和企业微信渠道 | 后续只选试点企业常用的一种渠道，完成身份、交办、提醒与成果回传的完整链路 |
| 能力复用 | 广场资源复制、绑定与权限保护 | 后续增加可试用的岗位样例和复制后的维护责任；不把共享直接等同于可随意修改源资源 |

其 README 路线图仍将群聊中的多员工沟通分工、面向高风险动作的细粒度审批策略列为未完成。发布说明中的多员工协作不能直接推导为上述路线图项已交付；这些方向不作为 Basic 首轮必须追平的成熟功能。对照的产出是迭代顺序与可验证体验，不涉及引入 StaffDeck 的运行时或复制其实现。

## 首次使用与日常交付问题

以下事实在审查基线下为 `Inspected`，关于用户负担和收益的判断为 `Inferred`。P0 表示首轮候选范围，具体最小交付以执行提案为准。

| 优先级与问题 | 已核对事实和语义 Owner | 用户影响与优化建议 |
|---|---|---|
| P0：首次任务缺少引导 | `web/src/components/ChatWelcome.vue` 展示形象、描述和资源数量；`EmployeeSquareView.vue` 提供开始对话和默认员工操作 | 用户需要自己组织完整指令。员工页增加典型任务、必要材料、交付格式和适用边界；保留自由对话，示例只填入草稿，由用户发送 |
| P0：资源数量与员工能力口径不同 | `ChatWelcome.vue` 的资源统计读取当前用户可访问资源，侧栏技能由员工配置与资源权限共同限定 | 用户会把可访问数量理解成员工可用能力。欢迎页改为员工任务说明；资源统计降级到有明确口径的详情，不能自动扩大员工配置或资源权限 |
| P0：创建完成与可以工作之间存在断点 | `web/src/components/model-management/AgentEditModal.vue` 的模型、工具和其他配置页签仅在编辑既有员工时展示 | 创建流程需要覆盖职责、能力、检查和试运行。形象改为可选，标识与后端放入高级设置；配置检查和真实试运行分别给结果 |
| P0：知识能力依赖需要用户理解技术规则 | `web/src/components/AgentRuntimeConfigForm.vue` 对已选择知识库但未选择 `knowledge-base` 技能显示提示 | 汇总为可处理的就绪问题，定位具体设置；访问范围继续由后端资源权限决定，不能以预检提示代替授权 |
| P0：工作记录与成果分散 | `web/src/components/TaskCenterDrawer.vue` 主要呈现知识处理和评估后台任务；会话、项目及定时任务各有入口 | 增加“我的工作”入口，让用户找回执行状态、待处理事项、原会话与成果。展示层复用持久事实，保持 Request、Run、定时 occurrence 和后台任务各自的状态语义 |
| P0：统计无样本仍显示满分 | 页面观察到无反馈时满意度为 100%；`backend/package/yuxi/repositories/dashboard_repository.py` 的整体统计和员工统计都在零反馈时返回 100 | 改为“暂无评价”，展示评价样本量；真实全部差评应保持 0%。统计与展示共同保留无数据语义 |
| P0：任务结束提示未表达业务结果 | `TaskCenterDrawer.vue` 提示执行完成仍可能存在内部问题，需要查看日志 | 知识处理按文件真实状态反馈成功、失败和待处理数量，未知结果明确显示待核对；为失败项提供操作入口 |
| 回归与收敛：导航名称和内容对应 | `9dd2ceab` 已拆分知识库、技能管理并删除重复工作台入口；创建页等仍使用智能体术语 | 回归独立入口、旧链接和普通用户路径；消费端优先使用数字员工、技能和项目，技术标识保留在高级配置及调试界面 |

深度研究员工的引导示例可以是“对比产品”：收集产品名称、比较维度、使用场景和交付格式，将输入生成可编辑的任务草稿。素材、工具或外网条件不满足时解释限制并提供适用替代任务。示例内容需要由业务负责人审核，不能宣传未经真实试运行的能力。

成果已有预览、下载和保存到个人空间能力，事实由 `web/src/components/AgentArtifactsCard.vue` 和后端 artifact 服务拥有。后续可增加采纳、要求修改、版本与项目归档；首轮先保证从工作记录准确找到对应成果。跨会话、跨 Run 的成果不能根据时间邻近关系猜测。

## 后续产品能力与企业化方向

以下差距均限定于已检查的源码与界面。“未发现完整入口”表示产品流程尚未在该范围内形成，不否认可以通过 API、脚本或定制集成实现部分能力。P1 为首轮之后优先评估，P2 由试点需求决定。

| 优先级与方向 | 当前基础与不足 | 建议的最小演进 |
|---|---|---|
| P1：岗位资料与标准任务 | Agent 保存名称、描述、形象和运行配置，职责边界和交付规范缺少明确展示 | 在资料研究、文档整理、周期报表中选择试点，配套示例材料、输出模板、验收标准和业务负责人 |
| P1：草稿、发布与回滚 | 员工编辑直接保存；运行记录不等于可管理的发布版本 | 草稿与正式服务分离，提供变更摘要、独立试运行、版本发布及恢复上一版本；实现前明确配置与知识变化的版本边界 |
| P1：业务评测闭环 | 已有知识库页面评估及 CLI/Langfuse 智能体评估 | 在员工配置页维护典型任务并比较改动前后结果；将差评案例纳入人工审阅后的回归集 |
| P1：可维护的 SOP | Skills 与子智能体支持多步骤执行，未发现面向业务搭建者的完整 SOP 编辑与发布入口 | 先支持固定步骤、必填输入、检查项和人工确认节点；有明确分支需求后再评估流程画布 |
| P1：企业渠道和主动触达 | API、通道与定时任务已存在；未发现现成的企微、飞书、钉钉渠道管理及任务通知界面 | 选择试点企业实际使用的一种渠道，完成交办、待确认提醒、交付通知和返回原任务；显示连接状态与失败处理方式 |
| P1：可理解的授权与审批 | 已有工具审批，选项为请求审批和完全信任；审查会话的选择不代表系统默认 | 展示读取范围、外部写入和发送能力；审批说明对象、影响及结果，技术参数可展开；由有权限者维护组织边界 |
| P1：成效与成本 | 已有消息、调用、Token、用户、工具成功率和反馈统计 | 增加任务采纳率、返工率、人工介入、首次可用成果时间及单位采纳任务成本；节省工时由人工基线和抽样复核支持 |
| P2：团队项目协作 | 员工和知识可共享，项目 repository 的访问以个人 uid 为边界 | 先验证受控成果分享、评论和交接需求，再决定项目成员、共同编辑和负责人接管；避免隐式扩大个人工作区权限 |
| P2：知识生命周期 | 已有解析、检索测试、引用、图谱与只读外部连接器 | 展示资料负责人、有效时间、更新状态和适用范围；过期资料与相互冲突依据给出明确处理路径 |
| P2：用户可控记忆 | 用户配置界面主要提供 Memory 启停开关 | 提供记忆内容、来源、编辑与逐条删除入口，明确个人、项目和员工之间的边界 |
| P2：部署后的开箱验收 | 已有部署、readiness 和离线安装说明 | 管理员顺序验证模型、知识检索、样例文件交付、普通账号使用；环境健康与任务成功分别展示 |

主要事实 Owner 为 `backend/package/yuxi/storage/postgres/models_business.py` 中的 Agent 资料、`agent_config_service.py` 的配置写入、`project_repository.py` 的项目可见性、`web/src/components/UserConfigSettingsCard.vue` 的记忆入口和 `ToolApprovalModeSelector.vue` 的审批选项。渠道与定时任务分别由 Agent invocation 路由和 scheduled-agent service 负责；后续演进在这些边界上形成独立方案和证据。
